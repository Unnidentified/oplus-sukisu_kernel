Repo: `Unnidentified/oplus-sukisu_kernel` @ `main` = `601469c` (2026-11-08). No open PRs; #14–#27 all merged.
Fork of `sakfi/OP_KSUN_FS`, kept in sync. Purpose: CI-built OnePlus GKI kernels with **SukiSU-Ultra** (KernelSU-Next fork) built in-tree (`builtin`) + **SUSFS**, packaged as flashable AnyKernel3 zips.

## 1. What the project is / how a build flows
- `configs/<aNN>/<MODEL>.json` = one build profile. Fields auto-map to `OP_*` env vars in the action (`jq to_entries | OP_<KEY>`).
- `.github/workflows/build-kernel-release.yml` (workflow_dispatch): `op_model` matches `model` or `model` prefix + `-`; plus `android_version_filter` (A14/A15/A16), `kernel_version_filter` (android16-6.12 …), `ksu_options` (default `[{"type":"ksun","hash":"builtin"}]`), `ksu_mode` (builtin|lkm).
- Build job runs `.github/actions/build-kernel/action.yml`: repo-sync from `manifests/<aNN>/<manifest>.xml` → toolchain from cached release → patches (WildKernels `kernel_patches` clone + repo-local `patches/`) → SukiSU via `setup.sh` → SUSFS → feature steps → `gki_defconfig` → make → AnyKernel3 zip.
- Zip name: `{MODEL}_{KERNEL_FULL_VER}[-SuSFS_{SUSVER}][_LKM].zip` (e.g. `OP15-COS17_android16-6.12.69-SuSFS_v2.3.0.zip`). Release step parses this format; release notes are short plain markdown generated by the workflow.

## 2. The OP15 / ColorOS 17 story (most important context)
- ColorOS 17 on OnePlus 15 = Android 17 userspace but kernel KMI stays **`android16-6.12`, generation 6** (stock 17.0.0.102 = `6.12.112-android16-6`). The old OP15 build (`6.12.23-android16-5`, gen 5, OnePlus common) does NOT boot on COS17.
- Two OP15 profiles:
  - `configs/a16/OP15.json` → `manifests/a16/oneplus_15_w.xml` (OnePlus `sm8850_b_16.0.0_oneplus_15`, 6.12.23, gen 5) → **ColorOS/OxygenOS 16** zips.
  - `configs/a16/OP15-COS17.json` → `manifests/a16/oneplus_15_6.12.69_gki_w.xml` (**AOSP GKI `kernel/common` @ `242e1a07` = 6.12.69**, gen 6, + OnePlus sm8850 modules/devicetree) → **ColorOS 17** zips. Has `susfs_hash: c6788e2…` pin.
- `bbg: false` on both OP15 profiles on purpose: Baseband Guard off so EFISP/bootloader-spoof chains work.

## 4. Patches/mechanisms added in this fork (all merged)
- SUSFS on GKI 6.12.69: pin `c6788e2` (gki-android16-6.12 tip, v2.3.0) + `patches/susfs-fix-task_mmu-sus-map-gki-6.12.patch` applied only when `task_mmu.c.rej` appears (upstream refactored `show_smaps_rollup` in 6.12.30+). Big patch rc=1 is tolerated (rc≥2 aborts) so reject-fixes run under `set -e`.
- `sukisu-builtin-priority-filter-kconfig.patch` + conditional `CONFIG_KSU_SUSFS_PRIORITY_UID_FILTER=y` when `susfs_def.h` has `CMD_SUSFS_SET_PRIORITY_UID_FILTER` (newer susfs guards decls/defs behind that config; SukiSU builtin Kconfig lacked the symbol).
- BORE scheduler: `patches/bore_6.12.patch` (ported from `Bouteillepleine/kernel_patches` experimental/), `OP_BORE`-gated step, plus sed fixing `set_protect_slice` to use `sysctl_sched_base_slice` (PR #27 — the patch ifdefs the old symbol away; build failed without it). `CONFIG_SCHED_BORE=y`, `sched_bore=1` from boot, toggle `/proc/sys/kernel/sched_bore`.
- ADIOS iosched: `patches/adios_ioscheduler_6.12.patch` (same source), `OP_ADIOS` gate, `CONFIG_MQ_IOSCHED_ADIOS=y` + default.
- IPv6 NAT: configs were already in IP_SET step; now also applies WildKernels `common/IPv6_NAT_FIX.patch` (hides `CONFIG_IP6_NF_NAT` from `/proc/config.gz`).
- MLGO: `mlgo: true` → KCFLAGS `-mllvm -regalloc-enable-advisor=release` (clang-r547379 prebuilt is `+mlgo`; same as WildKernels' mlgo input).
- WireGuard: already `CONFIG_WIREGUARD=y` in GKI defconfig.
- `hmbird` forced off for OP15 (#18): no `fengchi_OP15_A16.patch` exists upstream — it was a silent no-op.
